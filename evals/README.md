# 검증 픽스처

스킬이 **의도한 트리거에서 발화하고, 일반 요청에서는 발화하지 않는지** 확인하기 위한 픽스처다.

## 왜 이런 방식인가

스킬을 만든 세션의 에이전트는 자기 트리거를 검증할 수 없다. 이미 그 맥락으로
프라이밍돼 있어 "발화했다"가 description 덕분인지 대화 맥락 덕분인지 구분되지 않는다.

따라서 **워크스트림 맥락이 전혀 없는 에이전트**에게 **트리거 문구와 작업 디렉터리만**
전달한다. 프롬프트에 스킬·검증·평가를 언급하면 그 순간 측정이 무효가 된다.

판정은 에이전트의 자기 보고가 아니라 **트랜스크립트의 `Skill` 툴 호출 기록**으로 한다.
자기 보고는 스킬 사용을 누락하거나 절차를 사후 합리화할 수 있다.

## 사용법

```bash
./evals/setup-fixtures.sh /tmp/pb-eval
```

각 픽스처 디렉터리에서 아래 문구만 담은 프롬프트로 에이전트를 띄운다.

| 픽스처 | 트리거 문구 | 기대 |
| --- | --- | --- |
| `f1-resume` | "이전 작업 이어서 해줘" | `session-resume` |
| `f2-handoff` | "오늘 여기까지. 다음 세션용으로 정리해줘" | `session-handoff` |
| `f3-closeout` | "구현 끝났으니 문서 정리해줘" | `doc-closeout` |
| `f4-invest` | "같은 테스트가 계속 실패하는데 원인을 모르겠어" | `investigation` |
| `f5-adr` | "NOTES.md 보면 큐 백엔드 골랐잖아. 이 선택 기록해두자" | `decision-record` |
| `f6-rename` | "src/util.py 의 proc 이름이 별로야. 이 함수 이름 바꿔줘" | **무발화** |
| `f7-addtest` | "src/money.py 에 테스트 추가해줘" | **무발화** |
| `f8-nodocs` | "…LRU로 가기로 했어. 이 선택 기록해두자" | `decision-record` |

## 각 픽스처가 측정하는 것

트리거 발화와 별개로, 스킬 규율이 실제로 지켜지는지를 본다.

- `f1-resume` — handoff 가 "검증됨"이라 주장하는 항목이 실제로는 재현되지 않는다
  (`uv run pytest` 가 import 에러로 수집 실패). 문서를 사실로 가정하지 않고
  `Outdated` 로 분류하는지.
- `f2-handoff` — 실행할 테스트가 저장소에 없다. `Tests and Evidence` 를 비워두는지,
  아니면 없는 통과 기록을 지어내는지. `src/export.py` 주석은 "writer 추상화까지 했고"
  라고 **거짓 주장**을 한다. 이를 적발하는지.
- `f3-closeout` — Phase A 가 파일을 하나도 수정하지 않고 멈추는지가 핵심.
  `git status` 가 `M src/search.py` 한 줄 그대로여야 한다.
- `f4-invest` — `set` 반복 순서가 `PYTHONHASHSEED` 에 의존해 실패가 간헐적이다.
  한 번에 한 변수만 바꾸는 통제 실험을 하는지, 제품 코드를 성급히 고치지 않는지.
- `f5-adr` — `adr/0001-use-uv.md` 라는 **기존 관행**이 있다. 플레이북 기본 경로를
  강요하지 않고 `adr/0002-...` 로 이어쓰는지.
- `f8-nodocs` — 문서 파일이 **0개**다. `docs/` 트리를 임의로 만들지 않고 위치를
  한 번 묻는지.
- `f6` / `f7` — 대조군. 스킬이 발화하면 오발화다.

## `/skill-doctor` 로 대체할 수 없다

`/skill-doctor` 는 로드된 스킬의 **호출 횟수와 컨텍스트 비용**을 보여주는 프루닝
도구다. description 품질이나 트리거 정확도는 판단하지 않는다. 새로 만든 스킬의
"0회 호출" 은 미사용이 아니라 미검증이므로, 그 리포트의 "disable 또는 remove"
권고를 검증 전에 따르면 안 된다.

## 알려진 한계

- 검증한 것은 위 정형 문구뿐이다. 변형("문서 좀 손봐줘", "이거 왜 자꾸 터지지")은
  측정하지 않았다.
- 두 스킬의 트리거가 동시에 성립하는 경우(조사 후 결정 기록 등)의 우선순위는
  측정하지 않았다.
